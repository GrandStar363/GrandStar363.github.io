# Architecture Guidelines

Priority order when rules conflict: (1) don't break existing behavior,
(2) match existing conventions in this codebase, (3) keep diffs small and
focused, (4) the principles below.

## Structure

- Organize by feature/domain, not technical role. Keep a feature's files together.
- Features talk to each other only through their public interface (exports,
  contracts, injected dependencies), never by reaching into internals.
- Keep UI, business logic, data access, and external service calls in separate layers.

## Design

- One reason to change per function/module/class. Split when a unit does
  two unrelated things, not just because it's long.
- Prefer composition over inheritance.
- Don't add abstraction or configurability until there's a second real use case.
- Validate and parse input at system boundaries; trust typed data inside them.

## Making changes

- Fix the problem asked about. Don't refactor unrelated code; mention it instead.
- Remove code your change made dead (unused imports, variables, helpers).
  Don't delete other pre-existing code without asking.
- Ask before large restructures, new dependencies, or public API changes.

## How the rules map onto this project

Next.js App Router with static export (`output: "export"`), deployed to GitHub Pages at https://grandstar363.github.io/ and optionally to Netlify (`netlify.toml`).

| Layer                         | Path                   | May import                                              |
| ----------------------------- | ---------------------- | ------------------------------------------------------- |
| Ingestion (external contract) | `scripts/twine-sync/`  | `@/content/schema` only                                 |
| Content contract              | `src/content/`         | nothing UI                                              |
| Shared kernel                 | `src/shared/{ui,lib}`  | other `@/shared/*` only                                 |
| Features                      | `src/features/<name>/` | `./` siblings, `@/shared/*`, **types** from `@/content` |
| Composition                   | `src/app/`             | everything; the only place features meet                |

- ESLint enforces these import boundaries (`eslint.config.mjs`). Don't disable them; route the dependency through the composition layer instead.
- Each feature exposes only `index.ts`. Features receive data through props from `src/app`; they never read `@/content` values directly.
- Everything is a Server Component unless it needs the browser. Client components are leaf-level and rare.
- `src/content/profile.json` and `public/media/` are generated by `npm run sync`. Never hand-edit them. Fix the mapper or parser and re-sync.
- Hand-authored values (email, site URL, nav, featured stack) live in `src/content/site.config.ts`.
- Visual system: light only, warm white paper with sky-blue accents. Tokens live in `src/app/globals.css`; use them, not raw hex values.
